For all 7 payload structs in `payload/user.rs`, change every `pub field` to just `field` (private).

Add `pub fn new(...)` constructors to each struct. Parameter order matches current field declaration order.

Add getter methods where missing. Some structs already have getters (DeactivateUserPayload, ActivateUserPayload, ChangeRolePayload, GetUserByHandlePayload, ListUsersPayload). The structs needing NEW getters:

**CreateUserPayload** -- add:
- `pub fn handle(&self) -> &str`
- `pub fn name(&self) -> &str`
- `pub fn role(&self) -> UserRole`

**UpdateUserPayload** -- add:
- `pub fn id(&self) -> Uuid`
- `pub fn handle(&self) -> Option<&str>` (return `self.handle.as_deref()`)
- `pub fn name(&self) -> Option<&str>` (return `self.name.as_deref()`)

Note: `UpdateUserPayload::handle()` and `name()` return `Option<&str>` not `Option<String>` -- the usecase destructures via `if let Some(handle) = payload.handle` which must change to `if let Some(handle) = payload.handle().map(str::to_string)` or the usecase can call `payload.take_handle()` / `payload.take_name()` that returns `Option<String>`. Since the usecase needs owned strings to assign to `user.handle` and `user.name`, add ownership-transferring methods:
- `pub fn take_handle(&mut self) -> Option<String>` (uses `self.handle.take()`)
- `pub fn take_name(&mut self) -> Option<String>` (uses `self.name.take()`)

Similarly for CreateUserPayload, the usecase moves `payload.handle` and `payload.name` into a `User` struct. Add ownership-transferring methods:
- `pub fn into_parts(self) -> (String, String, UserRole)` -- destructures self, returns (handle, name, role)

This avoids cloning. The usecase calls `let (handle, name, role) = payload.into_parts();` after validation and the owner-role check.

Update the `#[cfg(test)]` module at the bottom of the file: change all struct literal constructions to use `::new(...)`. The tests are in the same file's `mod tests`, but since fields are private (not `pub`), even same-file submodules cannot access them -- `new()` is required.

Structs and their `new()` signatures:
1. `CreateUserPayload::new(handle: String, name: String, role: UserRole)`
2. `UpdateUserPayload::new(id: Uuid, handle: Option<String>, name: Option<String>)`
3. `ListUsersPayload::new(limit: u64, cursor: Option<String>, include_inactive: bool)`
4. `DeactivateUserPayload::new(target_id: Uuid, caller_id: Uuid, caller_role: UserRole)`
5. `ActivateUserPayload::new(target_id: Uuid, caller_id: Uuid, caller_role: UserRole)`
6. `ChangeRolePayload::new(target_id: Uuid, new_role: UserRole, caller_id: Uuid, caller_role: UserRole)`
7. `GetUserByHandlePayload::new(handle: String, caller_role: UserRole)`
