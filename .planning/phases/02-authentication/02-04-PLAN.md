**Note on WebAuthn testing (D-66):** webauthn-rs 0.5.4 provides testing support. The approach is:
- The server generates a challenge via `start_passkey_registration` / `start_passkey_authentication`
- For tests, we need a software authenticator that can respond to these challenges
- Check if `webauthn-rs` exports test utilities, or use `webauthn-authenticator-rs` crate
- If no convenient test authenticator is available, test at the gRPC level by:
  1. Calling `register_begin` to get challenge
  2. Using the returned challenge_id and a manually constructed response (may need `webauthn-authenticator-rs` as a dev-dependency)
- Alternative: test the domain modules directly (unit test webauthn.rs, session.rs, jwt.rs) and test gRPC routing separately with mock state
- If `webauthn-authenticator-rs` is not readily available or too complex to integrate, focus contract tests on non-WebAuthn RPCs (session, JWT, API key, admin) and test WebAuthn at the integration level with the full flow

Add `webauthn-authenticator-rs` as a dev-dependency in services/auth/Cargo.toml if available and compatible. If not, note this in the summary and test WebAuthn flows with mock credential data.
