**1. Create services/auth/src/webauthn.rs** following research Pattern 2 and Pattern 3:

```rust
use url::Url;
use webauthn_rs::prelude::*;
use redis::aio::ConnectionManager;
use redis::AsyncCommands;

const CHALLENGE_TTL_SECS: u64 = 300; // 5 minutes

pub fn build_webauthn(rp_id: &str, rp_origin: &str) -> WebauthnResult<Webauthn> {
    let origin = Url::parse(rp_origin)
        .map_err(|_| WebauthnError::InvalidRelyingPartyOrigin)?;
    WebauthnBuilder::new(rp_id, &origin)?
        .rp_name("Madome")
        .build()
}
```

Add functions:

**`registration_begin`**: Takes `&Webauthn`, `Uuid` (user_id), `&str` (user_name), `Option<Vec<CredentialID>>` (exclude_creds). Calls `webauthn.start_passkey_registration(user_id, user_name, user_name, exclude_creds)`. Returns `WebauthnResult<(CreationChallengeResponse, PasskeyRegistration)>`. Per D-10 (no attestation), D-11 (no restriction), D-12 (UV required), D-13 (resident key required) -- webauthn-rs `start_passkey_registration` with Passkey type handles these by default.

**`registration_finish`**: Takes `&Webauthn`, `&RegisterPublicKeyCredential`, `&PasskeyRegistration`. Calls `webauthn.finish_passkey_registration(credential, state)`. Returns `WebauthnResult<Passkey>`.

**`extract_aaguid`** (D-67): Takes `&[u8]` (raw attestationObject bytes from client registration response). Uses `minicbor::decode` to parse the CBOR map, extracts the `authData` byte string, then slices `authData[37..53]` to get the 16-byte AAGUID. Converts to `Uuid` via `uuid::Uuid::from_bytes`. Returns `Result<Uuid>`. This must be called BEFORE `registration_finish` since we need the raw client response bytes.

**`authentication_begin`**: Takes `&Webauthn`. Calls `webauthn.start_passkey_authentication(&[])` (empty slice for discoverable flow per D-17 / research Pattern 3). Returns `WebauthnResult<(RequestChallengeResponse, PasskeyAuthentication)>`.

**`authentication_finish`**: Takes `&Webauthn`, `&PublicKeyCredential`, `&PasskeyAuthentication`. Calls `webauthn.finish_passkey_authentication(credential, state)`. Returns `WebauthnResult<AuthenticationResult>`.

**Redis challenge state helpers:**

**`store_registration_challenge`**: Takes `&mut ConnectionManager`, `&str` (challenge_id), `&PasskeyRegistration`. Serializes state via `serde_json::to_string`, stores at key `reg_challenge:{challenge_id}` with 5-minute TTL.

**`get_registration_challenge`**: Takes `&mut ConnectionManager`, `&str` (challenge_id). Gets and deletes key `reg_challenge:{challenge_id}`. Deserializes `PasskeyRegistration`. Returns `Option<PasskeyRegistration>`.

**`store_authentication_challenge`**: Same pattern with key `auth_challenge:{challenge_id}` for `PasskeyAuthentication`.

**`get_authentication_challenge`**: Same pattern, returns `Option<PasskeyAuthentication>`.

**2. Create services/auth/src/session.rs** following research Pattern 7:

```rust
use redis::aio::ConnectionManager;
use redis::AsyncCommands;
use serde::{Serialize, Deserialize};

const SLIDING_TTL_SECS: u64 = 7 * 24 * 3600;     // 7 days (D-33)
const ABSOLUTE_TTL_SECS: i64 = 30 * 24 * 3600;   // 30 days (D-33)

#[derive(Debug, Serialize, Deserialize, Clone)]
pub struct SessionData {
    pub user_id: String,
    pub role: String,
    pub name: String,
    pub created_at: i64,
    pub last_refreshed_at: i64,
}
```

Add functions:

**`create_session`**: Takes `&mut ConnectionManager`, `&str` (session_id), `&SessionData`. Stores at `session:{session_id}` with `set_ex(SLIDING_TTL_SECS)`. Also `SADD user_sessions:{user_id} {session_id}` for the secondary index needed by `invalidate_all`.

**`validate_and_slide_session`**: Takes `&mut ConnectionManager`, `&str` (session_id). Gets `session:{session_id}`. If absent, returns `Ok(None)`. If present, deserializes `SessionData`, checks absolute TTL (`now - data.created_at > ABSOLUTE_TTL_SECS`), if expired deletes key + removes from user set and returns `Ok(None)`. Otherwise, updates `last_refreshed_at = now`, re-serializes, `set_ex` with `SLIDING_TTL_SECS`, returns `Ok(Some(data))`.

**`invalidate_session`**: Takes `&mut ConnectionManager`, `&str` (session_id). Gets session data first to extract user_id, then `DEL session:{session_id}` and `SREM user_sessions:{user_id} {session_id}`.

**`invalidate_all_sessions`**: Takes `&mut ConnectionManager`, `&str` (user_id). `SMEMBERS user_sessions:{user_id}` to get all session_ids, `DEL session:{sid}` for each, then `DEL user_sessions:{user_id}`.

Functions:

**`generate_invite_token`**: Uses `rand::rngs::OsRng` to generate `INVITE_TOKEN_BYTES` random bytes, encodes with `URL_SAFE_NO_PAD`. Returns raw token string.

**`invite_expires_at`**: Returns `chrono::Utc::now() + chrono::Duration::minutes(INVITE_EXPIRY_MINUTES)`.

Implement all RPCs from `AuthService` trait (generated by tonic from auth.proto). Each RPC method:
- Extracts request fields from the proto message
- Calls the appropriate domain module functions (webauthn, session, jwt, invite, recovery, api_key)
- Calls repository functions for DB operations
- Returns the proto response message

Key RPC implementations:

**`health`**: Return `Ok(Response::new(()))` (unchanged).

**`register_begin`** (D-16, D-01):
1. Hash the invite token, look up via `repository::invitation::find_by_token_hash`
2. Validate: not used, not expired -> return `Unauthenticated` status if invalid (D-52: generic `invite_invalid`)
3. Call `webauthn::registration_begin` with a new UUIDv4 user_id and the provided name
4. Store challenge state in Redis via `webauthn::store_registration_challenge`
5. Return `RegisterBeginResponse` with challenge_id and serialized `CreationChallengeResponse`

**`register_finish`** (D-16, D-01, D-67):
1. Retrieve challenge state from Redis via `webauthn::get_registration_challenge`
2. Extract AAGUID from raw `attestationObject` in the registration response: parse CBOR with minicbor to get `authData` bytes, then slice `authData[37..53]` as UUID (D-67)
3. Call `webauthn::registration_finish` with the credential
4. Create user via `repository::user::create_user` (UUIDv4, name from challenge state, role="user")
5. Store credential via `repository::credential::create_credential` (serialize `Passkey` to JSON, include extracted AAGUID)
6. Mark invite as used via `repository::invitation::mark_used`
6. Generate recovery codes via `recovery::generate_recovery_codes`, hash each, store via `repository::recovery_code::create_codes`
7. Create session via `session::create_session` (new UUIDv4 session_id)
8. Issue JWT via `jwt::get_or_issue_jwt`
9. Return `RegisterFinishResponse` with user_id, jwt, session_id, recovery codes (raw, unhashed)

**`login_begin`** (D-17):
1. Call `webauthn::authentication_begin`
2. Store challenge state in Redis
3. Return `LoginBeginResponse` with challenge_id and serialized `RequestChallengeResponse`

**`login_finish`** (D-17, D-02):
1. Retrieve challenge state from Redis
2. Load ALL credentials from DB (`repository::credential::find_all_credential_data`) -- deserialize each `Passkey` from JSON. Build a lookup map: `CredentialID -> (credential_id_uuid, user_id)`.
3. Call `webauthn::authentication_finish` with the credential and state
4. From `auth_result.cred_id()`, look up the corresponding user_id from the credential map
5. Check `auth_result.needs_update()` -- if true, call `passkey.update_credential(&auth_result)` and update DB via `repository::credential::update_credential_data` (research Pitfall 8)
6. Load user from DB, check `is_active` -- if not active, return `Unauthenticated` (D-53)
7. Create session, issue JWT
8. Return `LoginFinishResponse`

**`recover_begin`** (D-23):
1. Find user by name via `repository::user::find_by_name`
2. Validate recovery code: load unused codes via `repository::recovery_code::find_unused_by_user`, hash provided code, compare with stored hashes
3. If valid: mark code as used, call `webauthn::registration_begin` for new passkey
4. Store challenge state in Redis
5. Return `RecoverBeginResponse`

**`recover_finish`** (D-23, D-67):
1. Same flow as `register_finish` but: user already exists (no create), generate new recovery codes (delete old ones first per D-22), add new credential. Extract AAGUID from attestationObject via minicbor (same as register_finish)

**`validate_session`** (D-33):
1. Call `session::validate_and_slide_session`
2. Return `ValidateSessionResponse` with valid flag and user info

**`refresh_token`** (D-37, AUTH-05):
1. Call `session::validate_and_slide_session`
2. If valid, build claims and call `jwt::get_or_issue_jwt`
3. Return `RefreshTokenResponse` with new JWT

**`logout`** (D-36): Call `session::invalidate_session`.

**`logout_all`** (D-36): Call `session::invalidate_all_sessions`.

**`verify_api_key`** (D-31, GATE-05):
1. Hash the provided key via `api_key::hash_api_key`
2. Look up via `repository::api_key::find_by_key_hash`
3. Check is_active and expiry
4. Return `VerifyApiKeyResponse` with valid flag and scope="scraper"

**Passkey management RPCs** (D-19, D-20):
- `list_passkeys`: Query credentials by user_id, map to PasskeyInfo messages (include aaguid from DB column, D-67)
- `rename_passkey`: Call `repository::credential::rename`
- `delete_passkey`: Check `count_by_user_id >= 2` first (D-15), then delete
- `add_passkey_begin/finish`: Same as registration but for existing user. Extract AAGUID from attestationObject via minicbor (D-67)

**Recovery code RPCs** (D-22):
- `regenerate_recovery_codes`: Delete all existing, generate 10 new, store hashed, return raw

**Admin RPCs** (D-02, D-08, D-09):
- `create_invitation`: Generate token, hash, store via repository. Note: the gRPC request does NOT carry the admin user_id -- it should be passed via gRPC metadata (x-user-id) from the gateway. Extract from request metadata.
- `list_invitations`: Query all invitations
- `deactivate_user`: Set is_active=false via repository, then invalidate all sessions (D-38)
- `reactivate_user`: Set is_active=true
- `list_users`: Query all users
- `create_api_key`, `list_api_keys`, `revoke_api_key`: Delegate to repository + api_key module

For all error cases: use `tonic::Status::unauthenticated("unauthorized")` for auth failures (D-50), `tonic::Status::invalid_argument(msg)` for bad input, `tonic::Status::not_found(msg)` for missing resources. Log detailed errors with `tracing::warn!` including request context (D-54).
