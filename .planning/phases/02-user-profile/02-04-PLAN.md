**1. Create services/gateway/src/routes/users.rs** with REST route handlers per D-42~D-47.

Gateway is a pure REST-to-gRPC translator per D-65. No business logic, just convert REST request to gRPC request, call the user service, and convert gRPC response to REST response.

**Route plan per D-43~D-44:**
- Self-service routes (authenticated tier, future middleware):
  - `GET /v1/users/@me` -> `get_me` handler
  - `PATCH /v1/users/@me` -> `update_me` handler
- Admin routes (admin+ tier, future middleware):
  - `GET /v1/users` -> `list_users` handler
  - `GET /v1/users/:id` -> `get_user` handler
  - `PATCH /v1/users/:id/role` -> `change_role` handler
  - `POST /v1/users/:id/deactivate` -> `deactivate_user` handler
  - `POST /v1/users/:id/activate` -> `activate_user` handler

Note: Auth middleware does not exist yet (Phase 3). For now, register the routes without auth guards. The handlers will expect caller context to be available when auth middleware is added. For Phase 2, the handlers will still compile and be callable -- they just won't be protected.

**Temporary approach for Phase 2:** Since there is no JWT middleware yet, the handlers cannot extract caller_id and caller_role from a verified JWT. For now:
- `@me` routes: Accept `X-Caller-Id` and `X-Caller-Role` headers from the REST request (will be replaced by JWT claims in Phase 3). This keeps the routes testable.
- Admin routes: Same approach -- read caller context from headers.

**Handler implementations:**

```rust
use axum::{
    extract::{Path, Query, State},
    http::HeaderMap,
    Json,
    response::IntoResponse,
};
use madome_core::error::AppError;
use crate::state::AppState;
use madome_proto::user::*;
use serde::{Deserialize, Serialize};

// Response struct matching D-63: all user responses use identical fields
#[derive(Serialize)]
pub struct UserJson {
    pub id: String,
    pub handle: String,
    pub name: String,
    pub role: String,
    pub is_active: bool,
    pub created_at: String,  // RFC3339
    pub updated_at: String,  // RFC3339
}

impl From<UserResponse> for UserJson {
    fn from(r: UserResponse) -> Self {
        let role_str = match Role::try_from(r.role) {
            Ok(Role::User) => "user",
            Ok(Role::Admin) => "admin",
            Ok(Role::Owner) => "owner",
            _ => "unknown",
        };
        let created_at = r.created_at
            .map(|t| chrono::DateTime::from_timestamp(t.seconds, t.nanos as u32)
                .map(|dt| dt.to_rfc3339())
                .unwrap_or_default())
            .unwrap_or_default();
        let updated_at = r.updated_at
            .map(|t| chrono::DateTime::from_timestamp(t.seconds, t.nanos as u32)
                .map(|dt| dt.to_rfc3339())
                .unwrap_or_default())
            .unwrap_or_default();
        Self {
            id: r.id,
            handle: r.handle,
            name: r.name,
            role: role_str.to_string(),
            is_active: r.is_active,
            created_at,
            updated_at,
        }
    }
}
```

Helper function to extract caller context from HTTP headers and inject into gRPC metadata:

```rust
fn inject_caller_context(
    headers: &HeaderMap,
    request: &mut tonic::Request<impl std::any::Any>,
) -> Result<(), AppError> {
    if let Some(caller_id) = headers.get("x-caller-id") {
        request.metadata_mut().insert(
            "x-caller-id",
            caller_id.to_str()
                .map_err(|_| AppError::BadRequest("invalid x-caller-id".to_string()))?
                .parse()
                .map_err(|_| AppError::BadRequest("invalid x-caller-id".to_string()))?,
        );
    }
    if let Some(caller_role) = headers.get("x-caller-role") {
        request.metadata_mut().insert(
            "x-caller-role",
            caller_role.to_str()
                .map_err(|_| AppError::BadRequest("invalid x-caller-role".to_string()))?
                .parse()
                .map_err(|_| AppError::BadRequest("invalid x-caller-role".to_string()))?,
        );
    }
    Ok(())
}
```

**Route handlers:**

`get_me`: Extract caller_id from headers, build `GetUserRequest { id: caller_id }`, call `state.user_client.clone().get_user(request)`, map response to `UserJson`, return `Json(user_json)`.

`update_me`: Extract caller_id from headers, parse JSON body `{ "handle": Option<String>, "name": Option<String> }`, build `UpdateUserRequest { id: caller_id, handle, name }`, call gRPC, return updated user.

`list_users`: Parse query params `ListUsersQuery { limit: Option<i32>, cursor: Option<String>, include_inactive: Option<bool> }` (kebab-case per API conventions: `include-inactive`). Build `ListUsersRequest`. Call gRPC. Return `Json(users_json)` array with `X-Next-Cursor` response header per PROJECT.md pagination convention.

`get_user`: Extract `:id` path param, build `GetUserRequest`, call gRPC, return `Json(user_json)`.

`change_role`: Extract `:id` path param, parse JSON body `{ "role": String }`, convert role string to proto `Role` enum value, build `ChangeRoleRequest`, inject caller context into gRPC metadata, call gRPC.

`deactivate_user`: Extract `:id` path param, inject caller context, build `DeactivateUserRequest`, call gRPC.

`activate_user`: Extract `:id` path param, inject caller context, build `ActivateUserRequest`, call gRPC.

All handlers map gRPC errors to REST errors via `AppError::from(tonic::Status)` which already exists in madome-core.

**Note on query param naming:** Per PROJECT.md API conventions, query params use kebab-case. Serde rename `include_inactive` to `include-inactive`:
```rust

pub struct ListUsersQuery {

    pub cursor: Option<String>,
    #[serde(rename = "include-inactive")]
    pub include_inactive: Option<bool>,
}
```
